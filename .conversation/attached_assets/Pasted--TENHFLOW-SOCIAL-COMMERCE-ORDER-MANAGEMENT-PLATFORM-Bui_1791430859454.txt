# TENHFLOW — SOCIAL COMMERCE ORDER MANAGEMENT PLATFORM

Build a polished, production-quality SaaS web application called **TenhFlow**.

## 01 — PRODUCT

**Name:** TenhFlow

**Tagline:** From customer chat to confirmed order.

**Product type:** Social-commerce order management SaaS

**Primary market:** Cambodian online sellers

**Primary users:** Small and medium online sellers who sell products through Facebook, Messenger, Telegram, comments, and livestreams.

### Core problem

Many online sellers manage sales manually through:

* Facebook comments
* Facebook/Messenger conversations
* Telegram chats
* Livestream comments
* Phone calls
* Notes
* Excel/Google Sheets

A customer may say:

> “A12 black M x2”

The seller then has to manually:

1. Find the customer
2. Identify the product
3. Understand the product code
4. Record quantity
5. Ask for phone number
6. Ask for address
7. Calculate the price
8. Create an order
9. Track payment
10. Arrange delivery

This is slow, repetitive, and easy to get wrong.

### TenhFlow's solution

TenhFlow turns customer conversations into structured orders.

The main workflow is:

**Catch → Understand → Match → Confirm → Deliver → Track**

The product should feel like a tool built specifically for social sellers, NOT a generic CRM or ERP.

---

# 02 — PRODUCT PRINCIPLE

The main UX principle is:

> **The seller should spend their time selling, not copying information from chats into spreadsheets.**

Every feature should reduce manual work.

### Important UX rule

Never ask the seller to manually enter information that TenhFlow already knows.

If the system knows:

* Customer → reuse customer
* Product code → identify product
* Variant → select automatically
* Quantity → extract automatically
* Phone → reuse customer phone
* Address → reuse customer address
* Price → calculate automatically

The seller should mainly need to:

**Review → Confirm**
